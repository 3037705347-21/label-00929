# 探店达人营销平台

一个连接本地商家与探店达人（KOL/KOC）的数字化营销平台。

## How to Run

```bash
# 克隆项目后，在根目录执行
docker-compose up --build -d

# 查看服务状态
docker-compose ps

# 查看日志
docker-compose logs -f

# 停止服务
docker-compose down

# 停止并清除数据
docker-compose down -v
```

## 题目内容

一、 系统概述与核心目标
本系统旨在构建一个连接本地商家与探店达人（KOL/KOC）的数字化营销平台。其核心目标是实现商家探店任务发布、达人接单执行、内容创作分发、效果追踪与佣金结算的全流程线上化、自动化管理，最终提升商家营销效率、保障达人收益，并作为平台方实现可持续运营。

二、 详细功能需求模块
系统需围绕商家、达人、平台管理员三类角色设计。

1. 商家端功能需求
商家是需求的发起方和付费方，其核心诉求是高效找到合适达人并获取营销效果。
- 入驻与店铺管理：商家可注册账号，并完善店铺资料，包括店铺名称、地址、联系方式、所属品类、详细图文介绍等。后台需提供店铺信息的增删改查功能。
- 任务发布与管理：这是核心功能。商家应能创建探店任务，表单需包含：任务标题、详细要求（内容形式、发布平台、发布时间）、任务类型（"云探店"或"到店实探"）、指定推广的商品/套餐、对达人的要求（粉丝量级、内容风格、历史数据）、佣金设置（支持"一口价"固定费用或"CPS"按核销销售额分成比例）、任务总预算与有效期。发布任务前，商家账户需有足额预充值余额。
- 流程监控与订单管理：商家需有专属后台看板，实时跟踪已发布任务的报名情况，审核报名达人的资质，并跟踪任务执行进度（如达人提交脚本、拍摄素材、最终成片）。商家需能对达人提交的最终作品进行审核与确认完成。
- 数据看板与财务管理：商家需要直观的数据报表，查看每个任务带来的曝光量、互动数据（点赞、评论、收藏）、以及最重要的核销转化数据（通过推广链接或券码产生的实际消费）。同时，需有清晰的财务中心，显示账户余额、充值记录、每笔任务支出明细及对账单。

2. 达人端功能需求
达人是内容的创作者，系统需提供便捷的接单、创作与收益管理体验。
- 注册与资质认证：达人需注册并提交其内容平台账号（如抖音、小红书ID）、粉丝量截图、内容领域标签等资料，供平台审核。审核通过后方可解锁接单功能。
- 任务大厅与接单：前端需有任务列表首页，支持按地理位置、任务分类、佣金范围、商家品牌等条件进行筛选和搜索。达人可查看任务详情并报名。系统应支持"自由抢单"和平台基于匹配度的"定向派单"两种模式。
- 任务执行与交付：达人接单后，应在"我的任务"页面管理所有进行中的订单。系统需提供标准化的流程接口，允许达人按阶段提交脚本构思、拍摄素材或最终成品供商家/平台审核，并能通过内置沟通工具与任务方进行高效沟通。
- 收益中心与提现：达人需能清晰查看每笔任务的收益明细（基础佣金、CPS分成）、累计总收入、可提现金额及所有提现记录。系统需集成安全的第三方支付接口，支持达人自主发起提现申请，经平台审核后到账。

3. 平台管理后台功能需求
平台方需要强大的后台来管理整个生态，确保流程规范、内容合规与资金安全。
- 全局用户与内容审核：管理员需审核商家入驻资质与达人认证信息。同时，需对商家发布的任务要求、达人提交的内容素材及最终作品进行合规性审核，确保符合平台规范。
- 资金流与佣金结算管理：这是系统的核心盈利与安全环节。平台需设计完整的资金流闭环：商家预充值 → 发布任务时冻结部分余额 → 达人完成任务并审核通过 → 平台按规则结算（将商家支付的金额，扣除平台服务费后，发放给达人）。后台需有详细的资金流水、对账报表和达人提现审核功能。
- 宣传版块（内容广场）运营：此版块是平台的"发动机"，需精心运营。
  - 达人作品集展示：为每位达人开辟个人主页，集中展示其历史优质探店作品、数据表现及商家评价，作为其"数字名片"。
  - 爆款案例与趋势：设立"热门案例"专区，展示近期效果突出的探店内容及其核心数据（如播放量、转化率），为商家提供选人参考，为达人提供创作方向。
  - 标签化筛选与发现：允许商家通过达人内容风格（如搞笑、测评、Vlog）、粉丝画像、擅长品类等多维度标签，主动发现和筛选潜在合作对象。
- 系统配置与数据分析：包括平台基础参数设置（如分类管理、分成比例、提现规则）、首页运营位管理等。平台需要宏观数据看板，统计总用户数、任务发布与完成量、平台总流水、利润等，以支持运营决策。

三、 原生PHP系统架构设计与技术实现要点
采用原生PHP开发意味着需要从底层构建应用架构，并逐一实现上述所有复杂功能。

1. 系统架构设计
为实现代码结构清晰、易于维护，必须采用MVC（Model-View-Controller）模式进行开发。
- 模型层：负责所有业务逻辑和数据操作。
- 视图层：负责呈现用户界面。使用HTML、CSS和JavaScript构建所有页面。
- 控制层：作为中枢，接收所有用户请求，调用对应的模型进行处理，再将结果返回给相应的视图进行展示。

2. 数据库设计
主要数据表包括：用户表、商家详情表、达人信息表、任务表、任务订单表、作品表、资金账户表、资金流水表、宣传内容表、系统配置表、分类表等。

3. 核心功能实现
- 用户认证与权限控制：实现安全的会话（Session）管理机制和JWT认证。
- 文件上传与管理：安全的上传处理逻辑。
- 支付与资金安全：所有涉及余额变动的数据库操作使用事务（Transaction）。
- 前后端数据交互：使用AJAX技术进行前后端异步通信，后端提供返回JSON格式数据的API接口。

## 技术栈

- **后端**: PHP 8.x + MySQL 8.0 + MVC 架构
- **前端**: HTML5 + CSS3 + JavaScript (原生)
- **容器化**: Docker + Docker Compose
- **Web服务器**: Nginx

## 核心功能

### 商家端
- 店铺信息管理（含店铺城市）
- 任务发布与管理（云探店/到店实探、一口价/CPS分成）
- 达人报名审核（接受/拒绝）
- 订单管理与作品审核
- CPS核销数据录入（录入销售额，自动计算佣金）
- 数据看板（余额、任务、订单、支出统计）
- 财务中心（充值、交易记录）
- 内置沟通工具（与达人实时消息沟通）

### 达人端
- 个人资料与平台认证（含所在城市）
- 任务大厅（按任务类型、佣金范围筛选搜索）
- 推荐任务（定向派单，基于多维度智能匹配）
- 我的订单（执行、提交作品）
- 内置沟通工具（与商家实时消息沟通）
- 收益中心（余额、提现、提现记录）

### 管理后台
- 数据看板（用户、任务、订单、财务统计）
- 用户管理（商家/达人审核）
- 任务审核
- 作品审核
- 提现审核
- 分类管理
- 系统配置（平台费率、提现限额等）

## 主要特性

- 响应式设计，支持移动端访问
- 注册审核机制（商家/达人注册后需管理员审核通过才能登录）
- 完整的资金流闭环（充值→冻结→结算→提现）
- 作品审核通过自动结算佣金
- CPS佣金根据实际核销销售额计算
- 定向派单算法（基于多维度匹配度评分）
- 内置沟通工具（商家与达人实时消息）
- 中文错误提示信息
- 弹窗header/footer固定，内容区滚动
- 空状态页面居中显示
